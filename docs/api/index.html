IT Helpdesk API Reference

9 route, payload, response và lỗi được đối chiếu với mã nguồn DX-OS Open-Core tại SHA 0e789cf.

v0.1.0 · Pre-release

Phạm vi đã đối chiếu

v0.1.0 · Pre-release

Reference này chỉ bao gồm 9 route IT Helpdesk Backend có trong controller tại commit 0e789cffa11447f3acef25d0e582bf25ed46c7b4.

Controller chỉ được đăng ký khi dxos.helpdesk.enabled=true. Cấu hình còn bắt buộc HTTP loopback 127.0.0.1, cơ sở dữ liệu disposable và runtime login theo mẫu quy định. Các API Generic Workflow, BFF và Facility nằm ngoài phạm vi trang này.

Nguồn: HelpdeskConfiguration.java ↗ · SHA 0e789cffa11447f3acef25d0e582bf25ed46c7b4.

Danh tính và quyền

Backend dùng OAuth2 Resource Server/JWT; chỉ health được permitAll, các route Helpdesk yêu cầu danh tính đã xác thực. Service tiếp tục kiểm tra membership, tenant, quyền tài nguyên và technical authority. Tên vai trò trên UI không tự cấp quyền.

Hãy dùng allowedActions của response để định hướng thao tác. Server vẫn kiểm tra lại điều kiện khi ghi. Gửi body JSON bằng Content-Type: application/json; payload không khai báo tenant hoặc danh tính người gửi để client tự chọn.

Nguồn: SecurityConfig.java ↗ · SHA 0e789cffa11447f3acef25d0e582bf25ed46c7b4.

Nguồn: HelpdeskService.java ↗ · SHA 0e789cffa11447f3acef25d0e582bf25ed46c7b4.

POST/api/v1/mvp/requests

Tạo yêu cầu

Request body
Schema Create.
Response / hành vi
201 Created; response là RequestView. Header Location trỏ tới /api/v1/mvp/requests/{id}.

GET/api/v1/mvp/requests

Danh sách yêu cầu

Request body
Không khai báo request body.
Response / hành vi
Page { items, nextCursor }. after: UUID, không bắt buộc. limit: số nguyên 1–100, mặc định 50. items chỉ gồm yêu cầu đọc được; nextCursor là UUID hoặc null.

GET/api/v1/mvp/requests/{id}

Chi tiết yêu cầu

Request body
Không khai báo request body.
Response / hành vi
RequestView; id là UUID. Các trường tên hiển thị chỉ được đưa vào khi có dữ liệu; eligibleAssignees chỉ có ở chi tiết khi allowedActions chứa assign.

GET/api/v1/mvp/requests/{id}/history

Lịch sử chuyển trạng thái

Request body
Không khai báo request body.
Response / hành vi
Mảng HistoryView: transitionId, sourceState, targetState, version, occurredAt. Đây là lịch sử chuyển trạng thái Workflow; không suy diễn thành toàn bộ audit log hoặc lịch sử assignment.

Request body và version

SchemaTrường đã xác minh
Createtitle: string, không trống, tối đa 200 ký tự; description: string, không trống, tối đa 4000; requestType: bắt buộc và khớp IT_HELPDESK.
VersionexpectedVersion: số nguyên JSON không âm, bắt buộc; không nhận chuỗi hoặc số thập phân.
AssignassigneeId: string không trống, tối đa 1024; expectedAssignmentVersion: số nguyên JSON không âm, bắt buộc.
ResolveexpectedVersion: như Version; resolution: string không trống, tối đa 4000.

Cả bốn record request đều từ chối trường JSON không khai báo bằng @JsonAnySetter. Hai trường version dùng WorkflowVersionDeserializer, chỉ nhận token JSON số nguyên.

JSON · Ví dụ Create minh họa
{
  "title": "Không kết nối được Wi-Fi",
  "description": "Cần kiểm tra kết nối tại phòng họp.",
  "requestType": "IT_HELPDESK"
}

Ví dụ chỉ minh hoạ các trường đầu vào; không phải log hay kết quả chạy API.

Response đã xác minh

RequestView

TrườngKiểu / ngữ nghĩa
idUUID
title, description, requestTypeString; requestType trong service là IT_HELPDESK.
requesterId, assigneeId, resolutionString; assigneeId và resolution có thể null.
assignmentVersionlong; phiên bản phân công.
workflowInstanceId, stateString; định danh instance và trạng thái Workflow.
versionlong; runtimeVersion của Workflow.
allowedActionsList<String> theo quyền, vai trò và trạng thái tại thời điểm đọc.
requesterDisplayName, assigneeDisplayNameString tuỳ chọn; không xuất hiện khi null.
eligibleAssigneesDanh sách { id, displayName } tuỳ chọn; dành cho chi tiết có quyền assign.

Page và HistoryView

Page chứa items: List<RequestView> và nextCursor: UUID có thể null. Service sắp danh sách theo request UUID và áp dụng quyền đọc.

HistoryView chứa transitionId, sourceState, targetState (String), version (long), occurredAt (Instant).

Nguồn: Response records và view() trong HelpdeskService.java ↗ · SHA 0e789cffa11447f3acef25d0e582bf25ed46c7b4.

Lỗi và kết quả commit chưa rõ

ApiError gồm status (int), code (String), message (String) và errors (Map<String,String>). Bảng sau là các ánh xạ trong handler/security source, không phải cam kết mọi route đều tạo ra mọi lỗi.

HTTPCode / ranh giớiÝ nghĩa
400VALIDATION_FAILED / INVALID_BODYSai ràng buộc, tham số, JSON hoặc trường không được chấp nhận.
401Xác thực bắt buộcSecurityConfig yêu cầu authenticated cho các route này. Đây là ranh giới JWT resource server, không phải API đăng nhập.
403FORBIDDENThao tác không được phép.
404NOT_FOUNDKhông tồn tại hoặc bị ẩn; Helpdesk chuẩn hoá lỗi thiếu definition/instance thành cùng mã này.
409INSTANCE_ALREADY_EXISTS / VERSION_CONFLICT / TRANSITION_NOT_ALLOWED / INSTANCE_COMPLETEDXung đột instance, phiên bản hoặc trạng thái.
415UNSUPPORTED_MEDIA_TYPEBody cần application/json.
422INVALID_TRANSITIONHandler ánh xạ transition không hợp lệ.
500OPERATION_FAILURE / INTERNAL_ERRORLỗi thao tác hoặc lỗi nội bộ.
503AUTHORIZATION_UNAVAILABLE / COMMIT_OUTCOME_UNKNOWNKhông xác minh được quyền, hoặc chưa biết kết quả commit. Với COMMIT_OUTCOME_UNKNOWN, đối chiếu instance/history trước; không tự động retry ghi.
